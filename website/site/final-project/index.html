Final project

One dataset. Your questions. A notebook and a live app.

The lessons taught the tools and the projects showed them at work. Now it is your turn: one complete analysis of a dataset you have never seen, from the first look to a public dashboard.

The task

Pick one of the six datasets below and build two things:

1

An analysis notebook

Asks clear questions, cleans the data with every decision explained, explores it with the right charts, and ends with answers, conclusions and limitations.

2

A Streamlit app

Lets someone else explore what you found, deployed with a public link.

Required, in one GitHub repository:

WhatDetails
analysis.ipynbthe analysis notebook, executed, with its outputs saved
app.pythe Streamlit app
a public linkthe app deployed on Streamlit Community Cloud

Everything else (how you organise the files, which tools you use around them) is your choice. The structure further down is a suggestion.

The workflow

StageWhat it means
1. First lookshape, types, a few rows, the meaning of every column, missing values
2. Questions5–7 questions, each naming the columns it needs
3. Cleaningscope, types, missing values, duplicates, impossible values, outliers; a cleaning log
4. Feature engineeringthe columns that make the questions easier (dates, groups, ratios)
5. Univariateone column at a time: typical value, spread, shape
6. Bivariatetwo columns: what moves with what
7. Multivariatethree or more: does the pattern hold inside groups?
8. Answerseach question, answered with a number
9. Conclusionfindings, limitations, next steps
Appthe charts that carry the answers, with filters, in a Streamlit app

Suggested structure

my-project/
├── analysis.ipynb       required: the analysis, executed, with outputs
├── app.py               required: the Streamlit app
├── README.md            suggested: the question, key findings, a screenshot, the live link, how to run it
├── data/                suggested: the cleaned data the app reads (not the raw download if it is large)
├── charts.py            optional: one function per chart, shared by the notebook and the app
├── pyproject.toml       recommended (uv): the dependencies
└── uv.lock              recommended (uv): their exact versions

Build it as its own GitHub repository, so it can be deployed on its own.

charts.py (optional). Keep every chart in one function in charts.py and import it from both the notebook and the app. A chart is then written once, looks the same in both places, and a fix reaches both. It is a convenience, not a rule: drawing the charts directly in the notebook and in app.py is fine.

uv (recommended). uv records the exact version of every package in uv.lock, so the project runs the same on your laptop, on someone else's, and on Community Cloud, which installs from uv.lock; uv sync sets everything up in one command. Not mandatory: a requirements.txt works too. Community Cloud does need one dependency file (uv.lock, pyproject.toml or requirements.txt) next to app.py or at the root of the repository, or the deployed app will not find pandas or Plotly.

Before you call it finished

Analysis

  • Every column used is explained, and every cleaning decision says why.
  • Each question is answered with a number, not an impression.
  • Each chart has a title that states the finding, readable axis labels, and a sentence below it.
  • Comparisons use the right summary (median for skewed data, rates for groups of different sizes).
  • At least one pattern is checked inside groups before it is trusted.
  • The limitations are honest: what the data cannot tell.

App

  • It opens without errors, and every chart reads the filtered data.
  • An empty filter shows a message instead of a crash.
  • The data is loaded once (@st.cache_data).
  • It is deployed on Streamlit Community Cloud, and the link is in the README.

Repository

  • It holds analysis.ipynb (with outputs) and app.py, and the README links to the live app.
  • A fresh clone runs: uv sync then uv run streamlit run app.py (or pip install -r requirements.txt then streamlit run app.py).
  • No file over 100 MB, no secrets, no .venv/.

How to use the dataset pages

  • The questions are a starting point, not a checklist. Answer some of them, drop others, and add your own. The best projects find a question nobody wrote down.
  • Look before you clean. The "watch out" lists point at problems in the data, but they don't give the answer: deciding what to do is your job, and explaining why is part of the analysis.
  • Keep your files small. Push the cleaned data your app needs, not the raw download. GitHub refuses files over 100 MB.

Reading compressed and multi-file downloads

Many downloads are zips. pandas can read a .zip or .gz that holds one CSV directly. For a zip with several files, open the one you need:

import pandas as pd
import zipfile

df = pd.read_csv("data.csv.gz")               # one compressed CSV: read it directly

z = zipfile.ZipFile("download.zip")           # several files in one zip
print(z.namelist())
df = pd.read_csv(z.open("the_file_you_need.csv"))
